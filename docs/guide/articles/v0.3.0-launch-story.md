# Desktop Pet Mitarashi v0.3.0: Two Mascots, Codex Mode, and a Better Release Flow

<img src="/release-header-v0.3.0.svg" alt="Desktop Pet Mitarashi v0.3.0 release header">

`v0.3.0` is where Desktop Pet Mitarashi stops feeling like a single desktop toy and starts feeling like a small, polished desktop companion project. The update expands the app from one mascot window into a pair of independent desktop walkers, gives the project a Codex-aware behavior mode, and tightens the packaging and docs flow around the release itself.

## The App Now Feels More Alive

The biggest visible change is that the cat is no longer alone. `v0.3.0` launches both a cat and a penguin in separate transparent windows, and each mascot keeps its own movement rhythm. They still respond to the same tray-level mode changes, but they no longer look mechanically locked together.

That matters more than it sounds. When both mascots can take corners at slightly different times and drift with their own speed multipliers, the desktop starts to feel less like a repeated animation and more like a playful ambient layer.

## Movement Grew From A Line Into A Perimeter

Earlier builds focused on a simpler “walk along the bottom edge” feel. In `v0.3.0`, the renderer logic grows into full display-edge traversal. The mascots now snap to the perimeter, rotate through corners, and update their pose direction as they move around the screen.

This is the release where the project’s desktop-pet idea really matches the name. The mascots are no longer just running across one strip of pixels; they are exploring the border of the workspace.

## Codex Mode Makes The Mascot Reactive

Another important step is `Codex Mode`. The app now reads `.codex/state_5.sqlite`, samples recent Codex activity, and uses that live task signal to influence mascot movement.

That gives the project a stronger identity than a generic desktop mascot. It can act like a lightweight visual companion for people already working inside the Codex ecosystem, reflecting moments of activity without demanding attention.

## The Release Process Improved Too

This release is also about how the project ships. The build workflow now syncs the version from the pushed tag before packaging, so artifacts line up with the published release number. The repository also now includes a GitHub Pages docs site with English and Japanese pages, which means the release can ship with both binaries and readable documentation at the same time.

That combination matters for maintainability. It is easier to explain the project, easier to hand someone a release link, and easier to keep the public surface in sync with what the code actually does.

## Validation

- `npm run docs:build`
- `npm run build:win -- --publish never`
- GitHub Actions tag build for `v0.3.0` completed successfully for Windows, macOS, and Linux before the release notes were finalized.
